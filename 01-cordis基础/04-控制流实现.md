# Cordis 控制流深度解析

## 核心架构

Cordis 的控制流基于三个核心组件：

1. **Context（上下文）** - 依赖容器和作用域管理
2. **EventsService（事件服务）** - 事件派发和监听
3. **Fiber（纤程）** - 插件生命周期和资源管理

## 1. Context - 依赖容器

### Proxy 机制

Context 是一个 **Proxy 对象**，所有的属性访问都被拦截：

```typescript
class Context {
  constructor() {
    // 创建 Proxy 代理
    const self = new Proxy<this>(this, ReflectService.handler)
    this.root = self
    // ...
    return self  // 返回代理对象
  }
}
```

**属性访问流程**：

```typescript
// 用户代码
ctx.tools.register('echo', tool)

// 实际执行：
Proxy.get(target, 'tools')
  ↓
ReflectService.handler.get()
  ↓
触发 'internal/get' 事件
  ↓
查找服务实例
  ↓
返回 ToolsService 实例
```

### 作用域继承

```typescript
// extend() 创建子上下文
extend(meta = {}): this {
  // 原型链继承父上下文
  const self = Object.create(getTraceable(this, this))
  
  // 添加新属性
  for (const prop of Reflect.ownKeys(meta)) {
    Object.defineProperty(self, prop, 
      Reflect.getOwnPropertyDescriptor(meta, prop)!)
  }
  
  return self
}
```

**继承链**：

```
Root Context
    ↓ extend()
Child Context A
    ↓ extend()
Child Context A.1
```

### 服务隔离

```typescript
// isolate() 创建独立的服务作用域
isolate(name: string, label?: symbol) {
  const shadow = Object.create(this[symbols.isolate])
  shadow[name] = label ?? Symbol(name)  // 新作用域标签
  return this.extend({ [symbols.isolate]: shadow })
}
```

**用例**：

```typescript
// 全局 llm 服务
ctx.plugin(OpenAIAdapter)

// Agent A 使用自己的 llm
const agentACtx = ctx.isolate('llm')
agentACtx.plugin(ClaudeAdapter)  // 不影响全局

// Agent B 仍然使用 OpenAI
const agentBCtx = ctx.extend()
```

## 2. EventsService - 事件派发

### 五种派发模式

#### 1. emit - 触发即忘（Fire and Forget）

```typescript
emit(...args: any[]) {
  // 获取监听器
  const callbacks = this.dispatch('emit', args)
  
  // 同步调用，不等待返回值
  callbacks.map(cb => cb(...args))
  
  // 立即返回，不阻塞
}
```

**特点**：
- ✅ 同步执行
- ✅ 不等待 Promise
- ✅ 忽略返回值
- ✅ 不阻塞调用者

**用例**：通知性事件
```typescript
ctx.emit('user-login', userId)  // 立即返回
```

#### 2. parallel - 并发执行

```typescript
async parallel(...args: any[]) {
  const callbacks = this.dispatch('emit', args)
  
  // 并发执行所有监听器
  const results = await Promise.allSettled(
    callbacks.map(async cb => cb(...args))
  )
  
  // 如果有错误，抛出聚合错误
  const errors = results.filter(r => r.status === 'rejected')
  if (errors.length) {
    throw new AggregateError(errors.map(e => e.reason))
  }
}
```

**执行流程**：

```
开始
  ↓
并发启动所有监听器
  ↓
┌─────────┬─────────┬─────────┐
│Listener1│Listener2│Listener3│
└─────────┴─────────┴─────────┘
  ↓         ↓         ↓
等待所有完成
  ↓
收集错误（如果有）
  ↓
结束
```

**用例**：需要等待所有操作完成
```typescript
await ctx.parallel('session/save', session)
// 所有保存操作（数据库、云存储）都完成
```

#### 3. serial - 串行执行（可短路）

```typescript
async serial(...args: any[]) {
  const callbacks = this.dispatch('serial', args)
  
  // 按顺序执行
  for (const cb of callbacks) {
    const result = await cb(...args)
    
    // 检查是否短路
    if (isBailed(result)) return result
  }
}

// 短路条件
function isBailed(value: any) {
  return value !== null && 
         value !== false && 
         value !== undefined
}
```

**执行流程**：

```
开始
  ↓
Listener 1 → 返回 undefined
  ↓
Listener 2 → 返回 "result"  ← 短路！
  ↓
返回 "result"
  ✗ Listener 3 不执行
```

**用例**：查找第一个有效结果
```typescript
// 查找哪个服务可以处理请求
const handler = await ctx.serial('find-handler', request)
```

#### 4. bail - 同步短路

```typescript
bail(...args: any[]) {
  const callbacks = this.dispatch('bail', args)
  
  // 同步执行，遇到 bail 值立即返回
  for (const cb of callbacks) {
    const result = cb(...args)
    if (isBailed(result)) return result
  }
}
```

**对比 serial**：
- `bail`: 同步，不等待 Promise
- `serial`: 异步，等待每个监听器

#### 5. waterfall - 洋葱模型（中间件链）

```typescript
waterfall(...args: any[]) {
  const callbacks = this.dispatch('waterfall', args)
  const inner = args.pop()  // 最后一个参数是 next
  
  // 构建调用链
  const next = () => {
    const cb = callbacks.shift() ?? inner
    return cb(...args)
  }
  
  args.push(next)
  return next()  // 触发链条
}
```

**执行流程**：

```
waterfall('event', arg1, arg2, innerFn)
  ↓
next() → Listener1(arg1, arg2, next)
           ↓ 调用 next()
           next() → Listener2(arg1, arg2, next)
                      ↓ 调用 next()
                      next() → innerFn(arg1, arg2)
                                 ↓ 返回结果
                               ← 结果
                      ↓ 可以修改结果
                    ← 返回
           ↓ 可以修改结果
         ← 返回
  ↓
最终结果
```

**洋葱模型可视化**：

```typescript
// 注册监听器
ctx.on('agent/request', async (payload, next) => {
  console.log('1: before')
  const result = await next()
  console.log('1: after')
  return result
})

ctx.on('agent/request', async (payload, next) => {
  console.log('2: before')
  const result = await next()
  console.log('2: after')
  return result
})

// 派发
await ctx.waterfall('agent/request', payload, async () => {
  console.log('inner: execute')
  return 'final result'
})

// 输出：
// 1: before
// 2: before
// inner: execute
// 2: after
// 1: after
```

**用例**：
- 请求拦截
- 权限检查
- 缓存层
- 日志记录

### 监听器过滤

```typescript
dispatch(type: string, args: any[]) {
  // 提取可选的 thisArg（用于过滤）
  const thisArg = typeof args[0] === 'object' ? args.shift() : null
  const name: string = args.shift()
  
  // 获取过滤函数
  const filter = thisArg?.[Context.filter]
  
  // 过滤监听器
  return (this._hooks[name] || [])
    .filter(hook => 
      hook.global ||           // 全局监听器
      !filter ||               // 无过滤器
      filter.call(thisArg, hook.ctx)  // 通过过滤
    )
    .map(hook => hook.callback.bind(thisArg))
}
```

**过滤器用例**：

```typescript
// 只监听特定 session 的事件
ctx.on('session/event', (event) => {
  console.log(event)
}, {
  // 添加过滤器
  [Context.filter]: (hookCtx) => {
    return hookCtx.sessionId === 'my-session'
  }
})
```

## 3. Fiber - 生命周期管理

### 什么是 Fiber？

Fiber 是插件的**执行上下文**，管理：
- 插件状态（pending → active → disposed）
- 依赖关系
- 资源清理（disposers）

### 生命周期状态

```typescript
enum FiberState {
  PENDING = 0,    // 等待依赖
  LOADING = 1,    // 加载中
  ACTIVE = 2,     // 已激活
  FAILED = 3,     // 加载失败
  DISPOSED = 4    // 已销毁
}
```

### 状态转换

```
创建
  ↓
PENDING (等待依赖注入)
  ↓
LOADING (调用插件函数)
  ↓
ACTIVE (插件运行中)
  ↓
DISPOSED (插件卸载)
```

### Effect 系统

```typescript
class Fiber {
  _disposables = new DisposableList()
  
  effect(callback: () => (() => void) | void, label?: string) {
    // 检查状态
    this.assertActive()
    
    // 执行 setup
    const dispose = callback()
    
    // 存储 disposer
    if (dispose) {
      this._disposables.push(dispose)
    }
    
    // 返回取消函数
    return () => {
      if (dispose) {
        dispose()
        this._disposables.delete(dispose)
      }
    }
  }
  
  dispose() {
    // 倒序执行所有 disposers
    for (const dispose of this._disposables.reverse()) {
      dispose()
    }
    this._disposables.clear()
  }
}
```

**Effect 栈**：

```typescript
// 注册
const d1 = ctx.effect(() => {
  console.log('setup 1')
  return () => console.log('cleanup 1')
})

const d2 = ctx.effect(() => {
  console.log('setup 2')
  return () => console.log('cleanup 2')
})

// 输出：
// setup 1
// setup 2

// 卸载（LIFO 顺序）
ctx.dispose()
// 输出：
// cleanup 2
// cleanup 1
```

## 完整控制流示例

### 场景：执行一个工具

```typescript
// 1. 注册工具
ctx.tools.register('echo', {
  description: 'Echo text',
  parameters: { /* ... */ },
  async execute(args) {
    return args.text
  }
})

// 2. 添加拦截器
ctx.on('tools/pre-execute', async (call, next) => {
  console.log('pre: 检查权限')
  await next()
})

ctx.on('tools/execute', async (call, next) => {
  console.log('execute: 执行工具')
  return await next()
})

ctx.on('tools/post-execute', async (result, next) => {
  console.log('post: 记录日志')
  await next()
})

// 3. 执行工具
const result = await ctx.tools.execute({
  id: '1',
  name: 'echo',
  args: { text: 'hello' }
})
```

**实际执行流程**：

```
ctx.tools.execute(call)
  ↓
ToolsService.execute()
  ↓
await ctx.waterfall('tools/pre-execute', call)
  ↓ next()
  监听器: 检查权限
  ↓ next()
  内置逻辑: 参数验证
  ↓
await ctx.waterfall('tools/execute', call)
  ↓ next()
  监听器: 记录开始
  ↓ next()
  默认执行器: tool.execute(args)
  ↓ 返回 { id: '1', result: 'hello' }
  ↓
await ctx.waterfall('tools/post-execute', result)
  ↓ next()
  监听器: 记录日志
  ↓ next()
  监听器: 保存到 session
  ↓
返回 result
```

## 关键设计模式

### 1. 依赖注入

```typescript
// 服务声明依赖
class ToolsService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'tools')
  }
}
ToolsService.inject = ['systemPrompt']

// Cordis 自动排序
ctx.plugin(ToolsService)      // 等待 systemPrompt
ctx.plugin(SystemPromptService)  // 先激活
```

### 2. 洋葱模型

```typescript
// 外层：缓存
ctx.on('request', async (req, next) => {
  const cached = cache.get(req)
  if (cached) return cached
  const result = await next()
  cache.set(req, result)
  return result
})

// 中层：日志
ctx.on('request', async (req, next) => {
  console.log('start')
  const result = await next()
  console.log('end')
  return result
})

// 内层：实际执行
```

### 3. RAII (Resource Acquisition Is Initialization)

```typescript
ctx.effect(() => {
  // 获取资源
  const connection = db.connect()
  
  // 返回清理函数
  return () => {
    connection.close()
  }
})
```

### 4. 原型链继承

```typescript
// 不是深拷贝，而是原型链
const child = Object.create(parent)

// 读取：先查 child，再查 parent
child.service  // 继承自 parent

// 写入：只影响 child
child.service = newService  // parent 不变
```

2. ✅ **原型链继承** - 子上下文不复制父上下文
3. ✅ **五种派发模式** - 覆盖所有使用场景
4. ✅ **Fiber 生命周期** - 自动资源管理
5. ✅ **Effect 栈** - LIFO 清理顺序
