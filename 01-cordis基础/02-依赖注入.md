# Cordis 依赖注入

## 为什么需要依赖注入？

在传统的模块系统中，我们需要：
- 手动管理加载顺序
- 使用 import 硬编码依赖
- 难以替换实现

Cordis 的依赖注入解决了这些问题。

## 声明依赖

### 基本语法

```typescript
class MyService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'myService')
  }
}

// 声明依赖
MyService.inject = ['logger', 'database']
```

### 依赖的含义

- 插件**等待**这些服务就绪后才激活
- 可以安全地使用 `ctx.logger` 和 `ctx.database`
- 如果依赖不存在，插件不会被激活

## 可选依赖

使用 `?` 标记可选依赖：

```typescript
MyService.inject = {
  required: ['logger'],
  optional: ['cache']
}

// 或简写
MyService.inject = ['logger', '?cache']
```

在插件中检查：

```typescript
class MyService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'myService')
    
    if (ctx.cache) {
      // 使用缓存
    } else {
      // 不使用缓存
    }
  }
}
```

## 依赖解析顺序

Cordis 自动计算加载顺序：

```typescript
const ctx = new Context()

// 可以以任意顺序注册
ctx.plugin(DatabasePlugin)  // 依赖 logger
ctx.plugin(CachePlugin)     // 依赖 database
ctx.plugin(LoggerPlugin)    // 无依赖

// 实际执行顺序：
// 1. LoggerPlugin
// 2. DatabasePlugin (等待 logger)
// 3. CachePlugin (等待 database)
```

## 服务的访问

### 通过 Context 访问

```typescript
class MyService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'myService')
    
    // 访问其他服务
    ctx.logger.log('Service started')
    ctx.database.query('SELECT * FROM users')
  }
  
  async doWork() {
    // 在方法中也可以访问
    const data = await this.ctx.database.query('...')
    this.ctx.logger.log('Work done')
  }
}
```

### TypeScript 类型定义

需要扩展 Context 接口：

```typescript
declare module '@cordisjs/core' {
  interface Context {
    logger: Logger
    database: Database
    myService: MyService
  }
}
```

## 实际例子

### 工具系统的依赖

```typescript
// tools 依赖 systemPrompt
class ToolsService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'tools')
  }
  
  register(name: string, tool: Tool) {
    // 注册工具
    const schema = this.generateSchema(tool)
    
    // 使用 systemPrompt 服务
    this.ctx.systemPrompt.addToolSchema(name, schema)
  }
}

ToolsService.inject = ['systemPrompt']
```

### Agent Loop 的依赖

```typescript
// agent-loop 依赖多个服务
class AgentLoop extends Service {
  constructor(ctx: Context) {
    super(ctx, 'agentLoop')
  }
  
  async run(input: string) {
    // 使用依赖的服务
    const prompt = this.ctx.systemPrompt.build()
    const tools = this.ctx.tools.list()
    const response = await this.ctx.llm.chat(prompt, tools)
    
    // 记录到 session
    this.ctx.sessions.append({
      type: 'assistant/message',
      content: response
    })
  }
}

AgentLoop.inject = ['systemPrompt', 'tools', 'llm', 'sessions']
```

## 循环依赖处理

Cordis 检测循环依赖并报错：

```typescript
// ❌ 错误：循环依赖
class A extends Service {
  constructor(ctx: Context) { super(ctx, 'a') }
}
A.inject = ['b']

class B extends Service {
  constructor(ctx: Context) { super(ctx, 'b') }
}
B.inject = ['a']

// 解决方案：使用事件通信代替直接依赖
class A extends Service {
  constructor(ctx: Context) {
    super(ctx, 'a')
    ctx.on('b-ready', () => {
      // B 服务就绪的回调
    })
  }
}
```

## 依赖注入的优势

### 1. 松耦合
```typescript
// 不需要 import 具体实现
// import { Logger } from './logger'  ❌

// 只需要声明依赖
MyService.inject = ['logger']  ✅
```

### 2. 可替换
```typescript
// 开发环境
ctx.plugin(ConsoleLogger)

// 生产环境
ctx.plugin(FileLogger)

// MyService 自动使用正确的实现
ctx.plugin(MyService)
```

### 3. 易于测试
```typescript
// 测试时可以注入 mock
class MockLogger extends Service {
  constructor(ctx: Context) {
    super(ctx, 'logger')
  }
  log(msg: string) {
    // 记录日志用于断言
  }
}

const testCtx = new Context()
testCtx.plugin(MockLogger)
testCtx.plugin(MyService)
```

## deepseek-harness 的依赖图

```
llm (无依赖)
  ↓
systemPrompt (依赖 llm)
  ↓
tools (依赖 systemPrompt)
  ↓
sessions (依赖 tools)
  ↓
agentLoop (依赖 sessions, tools, systemPrompt, llm)
```

## 关键要点

1. ✅ **使用 inject 声明依赖** - 不用 import
2. ✅ **Cordis 自动排序** - 不用担心加载顺序
3. ✅ **通过 ctx 访问服务** - 不直接实例化
4. ✅ **避免循环依赖** - 使用事件通信
