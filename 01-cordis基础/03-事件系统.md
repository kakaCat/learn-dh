# Cordis 事件系统

## 为什么需要事件？

事件是插件间松耦合通信的方式：
- **避免循环依赖** - A 和 B 可以互相监听事件，不需要直接依赖
- **扩展点** - 其他插件可以监听和拦截行为
- **解耦** - 发送者不需要知道接收者

## 四种派发模式

### 1. emit - 广播（不等待）

用于通知性事件，不需要返回值：

```typescript
// 定义事件
interface Events {
  'user-login': (userId: string) => void
}

// 派发事件
ctx.emit('user-login', '123')

// 监听事件
ctx.on('user-login', (userId) => {
  console.log(`User ${userId} logged in`)
})
```

**特点：**
- ✅ 不阻塞
- ✅ 所有监听器按注册顺序执行
- ❌ 无返回值

### 2. waterfall - 瀑布（串行中间件）

用于可以被拦截或修改的请求：

```typescript
// 定义事件
interface Events {
  'tools/pre-execute': (call: ToolCall, next: Next) => Promise<void>
}

// 监听器1：验证权限
ctx.on('tools/pre-execute', async (call, next) => {
  if (!hasPermission(call.name)) {
    throw new Error('Permission denied')
  }
  await next() // 继续下一个监听器
})

// 监听器2：记录日志
ctx.on('tools/pre-execute', async (call, next) => {
  console.log(`Executing tool: ${call.name}`)
  await next()
})

// 派发
await ctx.waterfall('tools/pre-execute', toolCall)
```

**特点：**
- ✅ 按顺序执行
- ✅ 可以短路（不调用 next）
- ✅ 可以修改参数后传递
- ✅ 有返回值

**Waterfall 的三种用法：**

#### a) 观察并传递
```typescript
ctx.on('agent/request', async (messages, next) => {
  console.log('Request starting')
  const result = await next() // 获取下游结果
  console.log('Request done')
  return result
})
```

#### b) 修改参数
```typescript
ctx.on('agent/pre-step', async (messages, next) => {
  // 添加系统消息
  messages.unshift({ role: 'system', content: 'You are helpful' })
  return await next() // 传递修改后的参数
})
```

#### c) 短路拦截
```typescript
ctx.on('agent/request', async (messages, next) => {
  if (shouldUseCache(messages)) {
    return getCachedResponse(messages) // 不调用 next，直接返回
  }
  return await next()
})
```

### 3. parallel - 并行

用于需要等待所有监听器完成的场景：

```typescript
// 定义事件
interface Events {
  'session/save': (session: Session) => Promise<void>
}

// 监听器1：保存到数据库
ctx.on('session/save', async (session) => {
  await db.save(session)
})

// 监听器2：备份到云存储
ctx.on('session/save', async (session) => {
  await cloud.backup(session)
})

// 派发（等待所有监听器完成）
await ctx.parallel('session/save', session)
```

**特点：**
- ✅ 所有监听器并发执行
- ✅ 等待所有完成
- ❌ 无返回值

### 4. serial - 串行

用于需要按顺序执行并收集结果的场景：

```typescript
// 定义事件
interface Events {
  'tools/list': () => string[]
}

// 监听器1：返回文件工具
ctx.on('tools/list', () => {
  return ['read', 'write', 'list']
})

// 监听器2：返回网络工具
ctx.on('tools/list', () => {
  return ['fetch', 'download']
})

// 派发（收集所有返回值）
const results = await ctx.serial('tools/list')
// results = [['read', 'write', 'list'], ['fetch', 'download']]
```

**特点：**
- ✅ 按顺序执行
- ✅ 等待每个完成
- ✅ 收集所有返回值

## 事件定义

### TypeScript 类型声明

```typescript
// 声明事件
declare module '@cordisjs/core' {
  interface Events {
    // emit 事件
    'user-login': (userId: string) => void
    
    // waterfall 事件（需要 next）
    'tools/pre-execute': (call: ToolCall, next: Next) => Promise<void>
    
    // parallel 事件
    'session/save': (session: Session) => Promise<void>
    
    // serial 事件
    'tools/list': () => string[]
  }
}
```

### 事件命名约定

deepseek-harness 的命名规范：

- `domain/action` - 按领域分组
  - `agent/request` - agent 域的 request 事件
  - `tools/execute` - tools 域的 execute 事件
  - `session/event` - session 域的 event 事件

## deepseek-harness 的事件

### 持久化事件（Session Events）
记录到日志，可以重放：

```typescript
'session/event': (event: SessionEvent) => void
```

事件类型：
- `turn/start`, `turn/end`
- `step/start`, `step/end`
- `user/message`
- `assistant/message`, `assistant/chunk`
- `tool/call`, `tool/result`

### Agent 事件（实时）
携带 Agent 实例，用于拦截：

```typescript
'agent/pre-step': (messages: Message[], next: Next) => Promise<void>
'agent/request': (messages: Message[], next: Next) => Promise<Response>
'agent/turn-stopping': (agent: Agent) => Promise<void>
```

### 能力事件（Capability Events）
用于策略和适配器：

```typescript
'tools/pre-execute': (call: ToolCall, next: Next) => Promise<void>
'tools/execute': (call: ToolCall, next: Next) => Promise<ToolResult>
'tools/post-execute': (result: ToolResult, next: Next) => Promise<void>
'fs/read': (path: string, next: Next) => Promise<string>
```

## 实际例子

### 例子1：工具执行管道

```typescript
// 插件1：权限检查
ctx.on('tools/pre-execute', async (call, next) => {
  if (!call.approved) {
    throw new Error('Tool not approved')
  }
  await next()
})

// 插件2：执行工具
ctx.on('tools/execute', async (call, next) => {
  const tool = ctx.tools.get(call.name)
  const result = await tool.execute(call.args)
  return result
})

// 插件3：记录结果
ctx.on('tools/post-execute', async (result, next) => {
  ctx.logger.log(`Tool result: ${result}`)
  await next()
})
```

### 例子2：Agent 流程拦截

```typescript
// 添加系统提示
ctx.on('agent/pre-step', async (messages, next) => {
  messages.unshift({
    role: 'system',
    content: 'You are a helpful assistant'
  })
  await next()
})

// 缓存响应
ctx.on('agent/request', async (messages, next) => {
  const cacheKey = hash(messages)
  const cached = cache.get(cacheKey)
  
  if (cached) {
    return cached // 短路
  }
  
  const result = await next()
  cache.set(cacheKey, result)
  return result
})
```

### 例子3：会话保存

```typescript
// 保存到多个地方
ctx.on('session/save', async (session) => {
  await fs.writeFile(`sessions/${session.id}.json`, JSON.stringify(session))
})

ctx.on('session/save', async (session) => {
  await db.sessions.insert(session)
})

// 派发（两个监听器并行执行）
await ctx.parallel('session/save', session)
```

## 监听器选项

### prepend - 优先执行

```typescript
// 普通监听器
ctx.on('tools/execute', handler1)

// 优先执行的监听器
ctx.on('tools/execute', handler2, { prepend: true })

// 执行顺序：handler2 -> handler1
```

### once - 只执行一次

```typescript
ctx.once('agent/ready', () => {
  console.log('Agent started')
})
```

## 事件 vs 依赖注入

### 何时用依赖注入？
- 直接调用服务方法
- 需要返回值
- 明确的调用关系

```typescript
// ✅ 适合依赖注入
const tools = ctx.tools.list()
const result = await ctx.llm.chat(messages)
```

### 何时用事件？
- 扩展点（允许其他插件介入）
- 通知（不需要返回值）
- 避免循环依赖

```typescript
// ✅ 适合事件
ctx.emit('user-login', userId)
await ctx.waterfall('tools/pre-execute', call)
```

## 关键要点

1. ✅ **emit** - 通知，不等待，无返回值
2. ✅ **waterfall** - 中间件链，可拦截，有返回值
3. ✅ **parallel** - 并发执行，等待完成
4. ✅ **serial** - 串行执行，收集返回值
5. ✅ 事件用于扩展点，依赖注入用于直接调用
